# mod2 — HAGIWO generic drum/audio module (XIAO RP2350)

KiCad schematic reverse-engineered from `hardware/mod2.png` (the HAGIWO MOD2
schematic screenshot). **Schematic only — no PCB yet, by request.**

## How this project is built

Generated by `gen.py`, exactly like `hardware/mod1/`: an embedded symbol lib plus a
small layout engine that draws a **real wired schematic** — blocks (pot channels,
CV/gate front-ends, the TL072 op-amp stages, the MCP4822 DAC output, the
NeoPixel level-shifter, power) connected with actual orthogonal wires, junctions
and power symbols; only the XIAO's pins and a few cross-section signal hops are
labelled. Coordinates snap to the 1.27 mm grid. The dual TL072s are emitted as
proper **multi-unit** parts — units A and B are the signal halves, unit C is the
power-pin box — matching how the source drew U1A/U1B/U1C and U2A/U2B/U2C.

The **netlist** is reproduced faithfully — verified byte-for-byte against the
earlier label-only revision by diffing `kicad-cli sch export netlist` output (all
43 multi-pin nets, including the D9 backfeed guard, have identical membership).
Edit `gen.py` and rerun; do not hand-edit the `.kicad_sch`, it will be overwritten.

```sh
python3 gen.py                       # regenerate mod2.kicad_sch + mod2.kicad_pro
/Applications/KiCad/KiCad.app/Contents/MacOS/kicad-cli sch erc mod2.kicad_sch
```

`gen.py` prints a net report, hard-fails on any same-coordinate pin collision
(silent short) and on any net with < 2 pins. Edit `gen.py`, not the `.kicad_sch`.
ERC is clean apart from the expected headless-only `lib_symbol_issues` warnings.

## Circuit summary

- **MCU:** Seeed XIAO RP2350 (U3). **Socketed, not soldered** — plugs into two 1×7
  2.54 mm female headers so it lifts out for reflashing/replacement; the U3
  footprint is that 2×(1×7) THT socket field (placeholder land pattern in `gen.py`
  — verify the real Seeed XIAO row spacing before PCB). BOM has the header sockets,
  not the XIAO. Rails: bus **+5V** (pins 11,12 → `+5V_BUS` →
  **D9** series Schottky → XIAO 5V pad + peripherals), **+12V** (pins 9,10 → D1 →
  op-amp V+), **−12V** (pins 1,2 → D2 → op-amp V−), GND (pins 3–6). XIAO 3V3 is
  the ADC/clamp reference (C19 0.1u + C20 10u).
- **USB-backfeed guard (D9):** the XIAO's `5V` pad *is* USB VBUS with no isolation
  inside the module, so the bus +5V is fed through **D9** (SS14, 1A Schottky,
  1=K→on-board `+5V`, 2=A→`+5V_BUS`) instead of wired straight to the pad. D9
  conducts bus→pad only, so with the module racked **and** plugged into USB for
  serial debug, the rack's +5V can never backfeed into the host's USB port (and
  USB can't source the rack). Cost is ~0.3 V drop — the XIAO, 74AHCT1G125 and
  WS2812 all run fine at ~4.7 V in-rack; on the bench (USB only) VBUS powers the
  board through the pad and D9 is reverse-biased. This is Seeed's own prescribed
  series-Schottky fix for a XIAO 5V-pad + USB coexistence.
- **3 pots** (100k): POT1→A0, POT2→A1 (each 10k + 0.1u filter). **POT3** is
  buffered by **U1A** and summed with CV.
- **CV in** (J2): 10k+100k attenuator (220k bias) → **U1B** buffer.
- **Summing / offset (U2A):** inverting summer of buffered POT3 (R9 10k),
  buffered CV (R10 10k) and a −12V offset (R11 33k + R14 1k), feedback R15 10k →
  R16 1k → **A2** (22n filter C12 + dual Schottky clamp to 3V3/GND).
  Per the HAGIWO pin map, **CV shares A2 with POT3** — they are summed into one ADC input.
- **2 gate inputs** (J3=IN2→GPIO0, J4=IN1→GPIO7): 4.7k pulldown + 3.3k series +
  dual Schottky clamp to 3V3/GND.
- **Audio out — MCP4822 DAC** (U5, replaces the stock PWM path). A 12-bit dual SPI
  DAC gives a cleaner, more linear output than PWM+RC. **VoutA** → C18 1u AC-couple
  → **U2B** non-inverting gain (1 + R22 68k / R21 33k ≈ 3.1×) → R23 1k → OUT jack
  **J6** (R20 100k biases the U2B input to GND). U5 is on **hardware SPI0**: GPIO2
  = SCK, GPIO3 = SDI, GPIO4 = /CS; /LDAC tied to GND (immediate update). Powered
  from **+3V3** (logic-compatible; VoutA 0–2.048 V at gain 1×), C24 decoupling.
  **VoutB** is a spare 2nd channel, left unconnected (break out to a header if a
  future rev wants a second output). **GPIO1** (the old PWM pin) is now unused.
  - Firmware side: `Mod2Common` now exposes `mod2::audioWrite()` (PWM) and
    `mod2::dacWrite()`/`dacBegin()`/`audioTimerBegin()` (DAC). Existing firmwares
    still build on the PWM backend and run on current PWM boards; migrate each to
    `dacWrite()` when running on DAC hardware. The old PWM reconstruction filter
    (R17/R19, C13–C17, JP1, JP2) is removed.
- **Status NeoPixel** LED1 (Adafruit 4776 RGBW Mini Button) on GPIO5. Because the
  RP2350 is 3.3V logic, a **74AHCT1G125 buffer (U4)**, 5V-powered with OE tied low,
  lifts the data line to a clean 5V level; R24 is the data series resistor (470R),
  C21/C22 the decoupling. (Delete U4 and wire GPIO5 straight through if you'd
  rather gamble on 3.3V data over a short trace.) **Push button** SW1 on GPIO6
  (1k series, 0.1u debounce C11).
- **4th pot** RV4 (9mm, 100k) on the spare ADC pin **A3** (GP29, also the XIAO's
  battery-sense pin — free here), 10k + 0.1u like the others. GPIO2/3/4 remain free.

## Notes / assumptions

- **C1 (10u)** and **C4 (0.1u)** are read as the **+5V** rail bulk+bypass. The
  source image is low-resolution (963×673) and C1's exact rail is the one genuinely
  ambiguous spot; +5V is the electrically sensible reading (symmetric with the
  10u+0.1u decoupling on +12V and −12V). Change in `gen.py` if the physical board
  says otherwise.
- Diode/clamp parts are labelled `B5819W SL` per the source (a 1N5819-class
  Schottky in SOD); power diodes D1/D2 are 1N4148WS.
- Footprints are provisional placeholders; verify before any PCB work.
