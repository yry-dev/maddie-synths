# Eurorack Fused Power Bus Board - 20-way

20 Eurorack bus headers on a single PCB, **individually fused on all three rails**, with
main fusing, reverse-polarity clamping, transient protection and a +5V ideal diode at
the input.

**Two board shapes, same circuit.** Identical netlist, identical reference designators,
identical assembly BOM - only the outline and component placement differ:

| | Staggered | Single-row |
|---|---|---|
| Board | 296 x 96 mm | 414 x 62 mm |
| Headers | 2 staggered rows of 10 | 1 row of 20, 16 mm pitch |
| Files | `eurorack-busboard.*` | `eurorack-busboard-singlerow.*` |
| Verified on real KiCad | **yes** | **yes** - DRC, gerbers, drill |

Pick the staggered board if your case has depth and you want the ribbons to fan out.
Pick the single-row board if you need to sit the bus behind a single 104 HP row and
have length to spare rather than height.

One board per 104 HP row. Power comes in through a Molex Mini-Fit Jr, matching the
m-power supply.

Everything is generated by the Python in `generator/` - change the header count, pitch
or board size and re-run.

## Power input

Two **Molex Mini-Fit Jr 5569 2x3 right-angle** headers (Mouser 538-39-30-1060). **J21 vents off the top edge, J22 off the bottom
edge** - plug into whichever side your case wiring reaches.

Pinout, verified against the supply and cross-checked against its second connector
mounted 180 degrees opposite:

| Pin | Net |
|---|---|
| 1 | GND |
| 2 | **-12V** |
| 3 | GND |
| 4 | **+5V** |
| 5 | GND |
| 6 | **+12V** |

Three grounds, one per rail, since ground returns the sum of all three. A straight-through
Mini-Fit Jr cable joins the supply to this board directly.

**Use one connector only.** Both land on the same input nets ahead of the main fuses, so
feeding both from two supplies would parallel them - the one thing you must not do with
two supplies. Four 14 AWG solder pads (J23-J26) remain as a hard-wire alternative.

The connector holes fall inside the plane bands, so +12V and +5V are carried across the
input block on dedicated bridge traces rather than relying on a necked-down plane.

## Reference designators

Renumbered so KiCad's annotation checker is happy (it requires `<prefix><number>`),
with a simple decode rule:

| | |
|---|---|
| `J1`–`J20` | bus headers |
| `J21` / `J22` | Mini-Fit Jr inputs, top edge / bottom edge |
| `J23`–`J26` | 14 AWG wire pads: -12V, GND, +12V, +5V |
| header *n* fuses | `F(3n-2)` = -12V, `F(3n-1)` = +12V, `F(3n)` = +5V |
| `F61`–`F63` | main rail fuses: -12V, +12V, +5V |
| header *n* decoupling | `C(2n-1)` = +12V, `C(2n)` = -12V |
| `C41`–`C43` | bulk reservoir caps |
| `D1`–`D3` | reverse-polarity clamps |
| `D4`–`D6` | TVS clamps |
| `D7`–`D9` | rail LEDs: red -12V, green +12V, yellow +5V |
| `Q1`, `R1` | +5V ideal diode and its gate resistor |
| `R2`–`R4` | LED series resistors |
| `H1`–`H8` | M3 mounting holes |

So header 7's fuses are F19/F20/F21 and its decoupling is C13/C14.

## File format and validation

Written in **KiCad 7 format**, which KiCad 7, 8 and 9 all open (8 and 9 offer to
upgrade on save). This was deliberate: it is the format that could be checked against
a real KiCad parser rather than hand-verified.

Verified with `kicad-cli`:

- PCB loads, plots gerbers on all four copper layers plus silkscreen and Edge.Cuts, and exports drill files
- Schematic loads and exports a netlist with no annotation or connectivity warnings
- All 14 symbols render from the symbol library
- **74 nets in the schematic, 74 in the PCB, identical pin membership on every one**
- Board footprint graphics are byte-identical to the library copies

The schematic derives every pin-to-net assignment from the PCB at generation time, so
the two files cannot disagree about which pad of a polarised part goes where.

### DRC fixes applied

Two DRC rounds on real KiCad found and fixed the following.

**Round 1 - 365 violations, all cleared:**

| Violation | Count | Cause and fix |
|---|---|---|
| `tracks_crossing` | 5 | **Real shorts.** The geometry checker compared segment endpoints only, so two segments could cross while every endpoint sat far from the other. Checker now does a proper orientation test. GATE row link moved left of the CV traces; input wire pads sit directly on their lanes instead of dropping across them; +5V input lane moved to B.Cu. |
| `lib_footprint_mismatch` | 154 | Board footprints held pads only. They now embed library graphics verbatim. |
| `silk_over_copper` | 199 | Designators sat 1 mm from the footprint origin, landing on pads. |
| `track_dangling` | 4 | CV/GATE buses ran past the outermost pads; now trimmed to each row's pad extent. |
| `silk_overlap` | 3 | Same designator cause. |

**Round 2 - 218 violations, all cleared:**

| Violation | Count | Cause and fix |
|---|---|---|
| `lib_footprint_mismatch` | 13 | **The 8 M3 mounting holes had no drill** - they were silkscreen circles only, and the board would have arrived undrilled. Now carry a real 3.2 mm NPTH pad (confirmed: 8 holes on tool T7C3.200 in the drill file). The other 5 were pad shapes declared `oval` on the board but `circle` in the library. |
| `silk_overlap` | 145 | 154 designators on a dense board cannot all be legible. Only the 20 headers and the input block keep silkscreen designators (46); the 108 per-header fuses and capacitors moved to F.Fab, where they are identified by position and the numbering rule above. Plain outline silk dropped from the 1812/1206/0805 parts, keeping polarity marks on diodes, LEDs and electrolytics. |
| `silk_over_copper` | 58 | Same cause. |
| `silk_edge_clearance` | 2 | C43 and D3 moved clear of the board edge. |

Courtyards are deliberately omitted from both board and library. At this component
density they would generate a flood of overlap errors that would bury real problems,
and clearance is verified numerically instead (0 violations at 0.25 mm).

Run DRC and ERC yourself before ordering, and **fill the zones (`B`) before plotting
gerbers** — unfilled zones plot as empty planes and the gerber viewer will not look wrong.

**Every DRC violation on both boards is severity `warning`, and none is on copper.** The
breakdown for the single-row board is 155 `lib_footprint_mismatch`, 69 `silk_overlap`,
30 `silk_over_copper`, 4 `silk_edge_clearance` - the same four categories the staggered
board reports, in smaller numbers. `lib_footprint_mismatch` is one per footprint and is
expected: the board copies deliberately differ from the library ones, having had most
designators moved to F.Fab (see the DRC section above). The 4 `silk_edge_clearance`
warnings are the two Mini-Fit connector outlines crossing the board edge, which is the
point of a right-angle connector that vents off the edge.

Independent confirmation of the planes, from KiCad's own zone filler rather than from the
generator's checker: **each rail band fills as exactly one island** - +5V 2234.9 mm2,
+12V 4030.3 mm2, -12V 7025.2 mm2, one contiguous piece of copper each across the full
414 mm. A severed band would show two or more.

Run DRC and ERC yourself before ordering regardless - and fill the zones first.

### Layout

The 62 mm height is the constraint that shapes everything. Header pads occupy the middle
of the board, so the three plane bands are pushed to the edges: +5V at y 1.5-7.0, +12V at
9.0-19.0, -12V at 43.0-60.5. That leaves a free band of roughly 24 mm through the centre,
and the input block has to get six paths across it in the same stretch of X.

The block therefore uses **explicit lane assignment**. Every corridor is named at the top
of the input-block section of `generator/pcbgen_singlerow.py` - `TRUNK`, `JOG_T`, `JOG_B`,
`BRIDGE`, `LED_LANE` - and the routing code refers to nothing else. Three rules keep it
collision-free:

- horizontal runs own a Y, vertical runs own an X, and no two nets share one;
- **the three plane bridges run on B.Cu**, which in that window carries only the GND pour
  and the CV/GATE buses, so they never enter the F.Cu congestion at all. This is what
  makes the block tractable: it takes six crossings down to three;
- any path that must cross a connector's pad field detours to a named escape Y clearing
  both pad rows and the mounting-hole keepouts.

Two notes on the bridges. They are **not** load-bearing for continuity - the bands narrow
to 2.70 mm (+5V), 3.65 mm (+12V) and 6.35 mm (-12V) of inner copper beside the connectors
but never sever, which is checked automatically. They earn their place as a parallel
low-impedance path around the obstruction, not as a repair.

### Mounting holes

Nine, at y 57.5 across the board plus two in the input-block window. The staggered board's
y=31 centre line is unusable here: at 16 mm pitch a header plus its fuses and decoupling
occupies essentially the whole pitch at mid-height, leaving no free X. H9 is the extra one
- the header clusters leave a 108 mm unsupported span across the middle, and this is a
board people push connectors into.

This is the **only** BOM difference between the two variants: `BOM-singlerow.csv` lists
9 x M3 where `BOM.csv` lists 8. The assembly BOM (`jlc-bom-singlerow.csv`) is byte-identical
to the staggered one, because mounting holes are not fitted parts.

## 2. Bus pinout

Doepfer 16-pin standard, two pins per signal, counting from the red-stripe end:

| Column | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| Net | **-12V** | GND | GND | GND | **+12V** | **+5V** | CV | GATE |

The red stripe sits at the **bottom** edge of the board (silkscreen marks it). Headers
are shrouded and keyed, so a ribbon can't be inserted flipped.

Note the well-known flaw in this standard: +5V (col 6) is adjacent to +12V (col 5), so
a reversed connector shorts the two positive rails together rather than presenting a
clean reverse polarity. That is exactly why the +5V rail is fused per header here too.

## 3. Protection scheme

### Per header (39 fuses per board)

| Ref | Rail | Part | Notes |
|---|---|---|---|
| F*n*A | -12V | 1812 PTC, 1.1A hold / 2.2A trip | Bourns MF-MSMF110-2 |
| F*n*B | +12V | 1812 PTC, 1.1A hold / 2.2A trip | Bourns MF-MSMF110-2 |
| F*n*C | +5V | 1206 PTC, 0.5A hold | Littelfuse 1206L050YR |
| C*n*A/B | ±12V | 100n 0805 | local decoupling |

Series resistance is ~0.09 Ω typical for the 1812 parts, so a 300 mA module sees about
27 mV of drop — inaudible. If you have one unusually hungry module, fit a **0 Ω link**
in the same footprint instead of a PTC and it is simply unfused.

### At the input

- **F_MN12 / F_MP12** — 2.6A hold PTC on each ±12V rail
- **F_MP5** — 1.5A hold PTC on +5V
- **D_R1..3** — SS54 Schottky clamps, reverse-biased across each rail. If a rail is
  fed backwards these conduct hard and trip the main PTC instead of letting the
  reverse voltage reach the modules.
- **D_T1..3** — SMBJ13A / SMBJ6.0A TVS clamps for spikes and hot-patching transients
- **C_B1..3** — 220 µF bulk reservoir per rail
- **D_L1..3** — red / green / yellow rail indicators. A dark LED means a blown rail.

### What this does and does not save you from

Be clear-eyed about this, because it's the difference between "protected" and "feels
protected":

- **Shorted or failed module → contained.** Its own PTC trips in a second or two,
  the rest of the rack stays up, and you know exactly which slot to look at.
- **Backwards or off-by-one ribbon at the *module* end → the module still dies.** No
  bus-board fuse can prevent that; the damage happens inside the module before any
  current limit reacts. The keyed shrouded headers on this board only guarantee the
  *bus* end is correct. Check the module end every time.
- **Reverse polarity on the input wiring → caught** by the clamp diodes + main PTC.
- **Rail transients → clamped** by the TVS parts.

PTCs are resettable: remove the fault, power down for ~30 s, and the rail comes back.
They do not reset while still under fault current.

## 4. Board construction

- **270 × 62 mm, 4 layers**
- F.Cu — header pads, fuses, stubs
- In1.Cu — solid GND plane
- In2.Cu — three power bands: +5V (y 1.5–7), +12V (y 9–19), -12V (y 43–60.5)
- B.Cu — GND pour plus the CV and GATE buses
- Track/via: 0.8 mm stubs, 2–3 mm trunks, 0.9/0.45 and 1.2/0.6 mm vias
- 5 × M3 non-plated mounting holes

The generator carries its own geometry checker (segment/pad/via pair distances) and
currently reports **0 clearance violations at 0.25 mm**. That is not a substitute for
KiCad's DRC — run it — but it means the file shouldn't land on you full of shorts.

Standard 1 oz outer / 0.5 oz inner is sufficient: the narrowest current path is a
0.8 mm stub carrying one module. Ordering 2 oz outer costs little and does no harm.

A 270 mm board sits in "large board" pricing at most fabs. If that stings, set
`HDR_X_LEFT`/`HDR_X_RIGHT` in `generator/pcbgen.py` to 3 + 3 headers and re-run for a
~150 mm board, then use four per row.

## 5. Wiring it into your system

Recommended for two supplies across three 104 HP rows:

- **PSU #1** → row 1 (two boards) and row 2 (two boards)
- **PSU #2** → row 3 (two boards)

Rules that matter:

1. **Never tie the +12V or -12V outputs of the two supplies together.** They will not
   share load; the higher one hogs until it current-limits. Only the **0V** rails get
   bonded, with dedicated 16 AWG.
2. **Home-run each board.** Run a separate trunk from the supply to each bus board
   rather than daisy-chaining board to board. Use the screw terminal, or solder
   directly to the four heavy wire pads (W_N12 / W_GND / W_P12 / W_P5) for 14 AWG.
3. The input block sits at the **centre** of the board, which halves worst-case IR
   drop compared with feeding an end.
4. Put the noisy digital modules on the row fed by one supply and the analogue VCOs on
   the other. These are switching supplies, and their rail ripple gets worse under load —
   it may not suit some analogue oscillators.

Budget check: 26 all-4HP digital slots per row can approach 3.5–4 A on +12V, which is
why both supplies are in play. The +5V rail (1.5 A per supply) is usually the first
thing you run out of.

---

## 6. Assembly order

1. All SMD first: PTCs, 0805 caps, LEDs, resistors, SS54, TVS.
2. THT: bulk electrolytics (watch polarity — pad 1 is +), screw terminal, CV/GATE
   headers, then the 13 bus headers last so they sit flat.
3. Before fitting any module: power up bare and confirm all three LEDs light, then
   meter every header for -12 / GND / +12 / +5 against the table in section 2.
4. Fit modules one at a time, checking current after each.

## 7. Regenerating

Staggered board:

```bash
cd generator
python3 libgen.py     # writes out/eurorack_bus.pretty + .kicad_sym
python3 pcbgen.py     # writes out/eurorack-busboard.kicad_pcb + clearance report
python3 schgen.py     # writes out/eurorack-busboard.kicad_sch
python3 renumber.py   # renumbers refs in BOTH files (must run last)
python3 bom.py        # writes out/BOM.csv
python3 jlc.py        # writes out/jlc-bom.csv + out/jlc-cpl.csv
```

Single-row board - the schematic is shared, so only the PCB is regenerated:

```bash
cd generator
python3 pcbgen_singlerow.py                                  # + clearance report
python3 verify_singlerow.py                                  # connectivity + planes
python3 renumber.py out/eurorack-busboard-singlerow.kicad_pcb
python3 bom.py  out/eurorack-busboard-singlerow.kicad_pcb -singlerow
python3 jlc.py  out/eurorack-busboard-singlerow.kicad_pcb -singlerow
python3 preview_singlerow.py                                 # optional render
```

Both generators print a clearance report; keep it at zero. `verify_singlerow.py` is the
one that matters most - the clearance check will happily pass a track that goes nowhere,
so this one union-finds every net across tracks, vias, pads and zone polygons, and
separately samples each plane band every 0.1 mm looking for a sever. It exits non-zero
on failure, so it drops straight into a build script.

`drc.py` runs real KiCad DRC headlessly on either board:

```bash
python3 drc.py ../eurorack-busboard-singlerow.kicad_pcb /tmp/report.txt
```

It needs the `pcbnew` Python module (`apt-get install --no-install-recommends kicad`,
which also provides `kicad-cli`). KiCad 7's `kicad-cli` has no `pcb drc` subcommand -
that arrived in KiCad 8 - but the Python module exposes both the zone filler and the
DRC engine, which is what the GUI uses. The script fills zones before checking, because
DRC on unfilled zones silently skips every copper-pour interaction.

`bom.py` and `jlc.py` both take an optional board path and filename suffix. Both were
validated by regenerating the staggered board's shipped `BOM.csv`, `jlc-bom.csv` and
`jlc-cpl.csv` byte-for-byte. `jlc.py` uses `kicad-cli` for placements when it is
installed and falls back to reading footprint origins directly when it is not; the
fallback is what produced the byte-identical output above.
